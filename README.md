# TopoMosaic V1

TopoMosaic is a first playable implementation of one colored ordered-track puzzle system spanning:

- **2D:** square, hexagonal, and triangular cells;
- **2D + time:** every frame has spatial clues and every cell has a temporal clue;
- **3D:** simple-cubic, FCC, BCC, and HCP lattices;
- **3D + time:** an evolving voxel/polycell structure constrained in both space and time.

The implementation is intentionally one app and one solver, not fourteen unrelated minigames.

## What is complete in this V1

- Four entry modes: 2D, 2D + Time, 3D, and 3D + Time.
- Seven supported geometries and fourteen authored demonstration puzzles.
- Ordered multi-color run clues, including the rule that different colors may touch while two runs of the same color require an empty separator.
- Generalized finite ordered tracks rather than hard-coded rows and columns.
- Temporal tracks generated for every spatial cell.
- A generic constraint solver with propagation, logical hints, contradiction detection, and uniqueness checking.
- Three-dimensional **Model**, **Slice**, and **Track** views.
- Space-filling Voronoi/Wigner–Seitz display cells for SC, FCC, BCC, and HCP.
- Explicit editing tools: Paint, Empty, Clear, Inspect, and Move/Orbit.
- Timeline playback, frame navigation, and previous-frame ghosting.
- Semantic model parts for objects and material structures.
- Undo, redo, local save, reset, soft checking, optional strict checking, keyboard controls, and mobile controls.
- English and Traditional Chinese UI.
- Installable PWA shell and a no-build local server.
- A tested integration script for the current Topoboardgame launcher/build structure.

## Start the standalone app

No installation is required for the 2D engine.

```bash
cd topomosaic-v1
npm run serve
```

Open:

```text
http://127.0.0.1:4173/
```

The Three.js 3D viewer is loaded through the same pinned Three.js version used by the current Topoboard project. The ordered Track panel remains an accessible editing fallback if WebGL or the external module fails to load.

## Integrate into Topoboardgame

From this kit:

```bash
node scripts/integrate-into-topoboard.mjs /absolute/path/to/Topoboardgame
```

The script is idempotent. It:

1. copies `mosaic/` to the repository root;
2. adds `mosaic/` to `tools/build-website.mjs`;
3. adds launcher links under 2D, 3D, 2+1D, and 3+1D;
4. adds English and Chinese launcher translations.

Then run the normal Topoboard build command, for example:

```bash
npm run build:web
```

Direct routes are:

```text
./mosaic/?dimension=2&time=0&lattice=square
./mosaic/?dimension=2&time=1&lattice=square
./mosaic/?dimension=3&time=0&lattice=sc
./mosaic/?dimension=3&time=1&lattice=sc
```

The app also accepts `puzzle=<puzzle-id>` and `lang=en|zh`.

## Shared rule model

For spatial cell set `V`, frame set `T`, and colors `1...K`, the player state is

```text
S : V × T → {unknown, empty, color_1, ..., color_K}.
```

A track is an ordered list of variables:

```text
τ = (u_1, u_2, ..., u_m).
```

Its clue is the run-length encoding of non-empty colors:

```text
R(τ) = [(color_a, length_a), ...].
```

Spatial tracks are generated by each lattice adapter and copied into every frame. When `frameCount > 1`, one temporal track is added for every cell:

```text
(cell, t_0) → (cell, t_1) → ... → (cell, t_n).
```

This is why time is a true logic direction rather than a timer or a post-completion animation.

## Geometry model

| Mode | Lattice | Primary clue tracks | Display cell |
|---|---|---|---|
| 2D | Square | rows and columns | square |
| 2D | Hexagonal cells | three axial families | hexagon |
| 2D | Triangular cells | three highlighted zigzag strip families | triangle |
| 3D | SC | X, Y, Z | cube |
| 3D | FCC | six nearest-neighbour face-diagonal families | rhombic dodecahedron |
| 3D | BCC | four body-diagonal and three optional axial families | truncated octahedron |
| 3D | HCP | three basal and one axial family, retaining A/B basis | HCP Voronoi polycell |

The solver never depends on the polygon or polyhedron. It sees only variable IDs and ordered tracks. This separation allows later additions such as Penrose tilings, irregular authored paths, body-centered tetragonal lattices, or graph-based puzzles without rewriting the solver.

## 3D interaction contract

**Model view** provides overall context and free camera inspection.

**Slice view** displays one crystallographic plane/layer at a time so internal cells remain selectable.

**Track view** isolates exactly one clue line and draws a rail through its ordered cells. The same line is flattened into accessible buttons in the right panel, providing a precise alternative to ray-casting in a dense model.

Camera and editing are deliberately separated:

- Paint/Empty/Clear: left click or tap edits cells;
- Move/Orbit: one-pointer camera control;
- right drag rotates even outside Orbit mode;
- two-finger gestures pan/zoom;
- Fit always restores the complete model;
- the track strip allows keyboard and single-pointer editing without dragging.

## Validation

Run:

```bash
npm test
npm run validate
```

The test suite verifies clue encoding, color-separation rules, track membership, finite lattice construction, and Voronoi geometry. The catalog validator verifies that every bundled puzzle:

- has a solution;
- has exactly one solution within the checked search;
- reproduces the authored answer;
- has at least one logical propagation path;
- does not require guessing in its initial authored state.

## Deliberate V1 boundaries

This is a complete **first playable version**, not the final content platform. V1 does not yet include user uploads, automatic image/mesh conversion, cloud sync, community publishing, moderation, adaptive difficulty, medical-data import, BIM import, or a production-scale content pipeline. Those belong after usability tests confirm that players understand temporal clues and can comfortably solve internal 3D tracks.

See `docs/PRODUCT_SPEC.md`, `docs/PUZZLE_AUTHORING.md`, and `docs/QA_CHECKLIST.md` for the exact product contract and next implementation gates.
